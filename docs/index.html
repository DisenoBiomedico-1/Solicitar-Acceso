Cómo instalar tu propia copia de un sistema de gestión para el curso de Diseño Biomédico 1 en GitHub

Este documento explica cómo replicar, en una organización de GitHub propia, un conjunto de herramientas que reemplaza a GitHub Classroom para el curso de Diseño Biomédico 1 de la UAO, organizado en retos semanales por equipo: crea automáticamente un repositorio por equipo a partir de una plantilla, invita a los estudiantes, publica los retos como issues con sus fechas de entrega, y genera un Project Board de seguimiento. El resultado queda bajo control total de quien lo instala, sin depender del origen de esta guía ni de que alguien más lo mantenga.

Qué vas a tener al final

  • Una plantilla de repositorio para cada grupo. Con ella, los estudiantes aprenden a usar GitHub como herramienta de documentación mientras resuelven retos semanales sobre los temas del curso de Diseño Biomédico 1. El resultado final es un Design History File (DHF), la designación internacional equivalente es Design Development File (DDF). La FDA (21 CFR Parte 820.30) y la norma ISO 13485 exigen ese DHF/DDF.
  • Un repo de administración que, a partir de un CSV con los integrantes de cada equipo, crea el repo del equipo, invita a los estudiantes, siembra los 18 Retos como issues con sus milestones, y crea un Project Board. Todo automático.
  • Un sistema de fechas de entrega: se editan en un solo archivo (fechas-retos.csv) y se propagan solas a todos los issues ya creados.

Requisitos previos

  • Una cuenta de GitHub (el plan gratuito es suficiente).
  • Diez minutos para ejecutar un conjunto de comandos, una sola vez.
  • Acceso de lectura a los repos plantilla, solicitado con anticipación. Solicítalo aquí. Esta solicitud requiere aprobación manual de un administrador de DisenoBiomedico-1, así que conviene enviarla antes de empezar los pasos siguientes: mientras se aprueba, puedes avanzar con el resto sin interrupciones.

Elige tu camino

Los Pasos 1 a 3 son comunes a ambos caminos y aparecen siempre abajo.

1 Crea tu organización

  1. Accede a github.com/account/organizations/new.
  2. Selecciona el plan gratuito.
  3. Anota el nombre exacto de la organización (por ejemplo, MiOrg-DB1).

2 Genera tu propio token de administración

Accede a github.com/settings/personal-access-tokens/new y configura:

  • Token name: el nombre es de uso interno, cualquier valor descriptivo sirve, por ejemplo ORG_ADMIN_TOKEN-TU-ORG.
  • Resource owner: la organización nueva.
  • Repository access: All repositories.
  • Permissions:
    • Organización → Administration: Read and write.
    • Organización → Projects: Read and write.
    • Repositorio → Administration: Read and write.
    • Repositorio → Contents: Read and write.
    • Repositorio → Issues: Read and write.
    • Repositorio → Secrets: Read and write.
    • Repositorio → Workflows: Read and write.
No compartas este token ni lo pegues en ningún chat, issue o PR.

3 Clona ambos repos, con "Use this template"

En cada uno de los dos repos:

  1. Botón verde "Use this template" → "Create a new repository".
  2. Owner: la organización nueva, no la cuenta personal.
  3. Nombre: el mismo (Plantilla-Diseno1, curso-admin) u otro a elección.
  4. Visibilidad: privado.

Repite el procedimiento con los dos repos.

4 Ejecuta el script automático Camino automático

Este script ejecuta los Pasos 5 a 7.

pip install requests pynacl
python3 replicar_en_tu_org.py --org TU-ORG-NUEVA

Si no se pasa --token, el script lo solicita de forma oculta. Al finalizar, continúa en el Paso 8.

5 Adapta el nombre de tu organización en los scripts Camino manual

El nombre de la organización de origen aparece como variable al inicio de varios scripts. En la copia de curso-admin, busca y reemplaza DisenoBiomedico-1 por el nombre de la organización nueva en estos archivos:

  • scripts/crear_repos_grupos.sh (dos apariciones: ORG= y TEMPLATE=)
  • scripts/reasignar_certificados.sh
  • scripts/vincular_project.sh
  • scripts/listar_projects.sh
  • scripts/agregar_estudiante.sh
  • scripts/borrar_projects.sh
  • scripts/borrar_repo.sh
  • scripts/crear_project.sh
  • .github/workflows/actualizar-fechas.yml (una aparición, dentro del comando que llama a crear_issues_iniciales.sh)

El reemplazo puede hacerse desde GitHub (editando cada archivo en el navegador) o desde un clon local del repo.

6 Guarda el token como secret Camino manual

En la copia de curso-admin: Settings → Secrets and variables → Actions → New repository secret → nombre ORG_ADMIN_TOKEN → valor: el token generado en el Paso 2.

7 Configura los privilegios de tu organización Camino manual

En github.com/organizations/TU-ORG/settings/member_privileges, configura:

  • Base permissions: "No permissions".
  • Repository creation: restringido a Private repositories only si tu plan lo permite. En el plan gratuito de organización, GitHub no ofrece esa restricción (solo "todos los tipos" o "ninguno"): si te importa acotarlo, requiere un plan Team o superior.
  • Allow forking of private repositories: desactivado.

8 Completa tus datos

  • curso-admin/roster/*.csv: los grupos, un archivo por grupo u horario.
  • curso-admin/scripts/issues_iniciales/fechas-retos.csv: las fechas del semestre. Formato id;fecha; los 16 Retos ya están listados, resta completar la columna de fecha.
  • Los 18 .md de issues_iniciales/: contenido editable según el estilo de clase o los casos de cada profesor.
  • Opcional: crear un repo de material (lecturas, presentaciones, anexos) y enlazarlo desde el README de la plantilla, con el patrón {{PROFESOR}} / MATERIAL_INICIO/MATERIAL_FIN que trae Plantilla-Diseno1. Si la organización tiene un solo profesor, el material puede incorporarse directamente en la plantilla.

9 Prueba con una fila de prueba antes de usarlo con estudiantes reales

  1. Agrega una fila de prueba a un roster con un usuario de GitHub de prueba.
  2. Ejecuta crear-repos-grupos.yml manualmente desde la pestaña Actions.
  3. Verifica que el repo, los 18 issues, el Project Board y el README queden correctos.
  4. Carga los rosters reales solo después de completar esta verificación.
Mantenimiento: esta copia queda bajo responsabilidad exclusiva de quien la administra. Correcciones y mejoras se aplican directamente sobre ella; no se sincronizan automáticamente con DisenoBiomedico-1 en ninguna dirección.
